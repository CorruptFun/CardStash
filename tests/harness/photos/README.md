# Real card photographs

Every fixture on the `harness-fixtures` branch is a flat SCAN. TCGplayer and
TCGdex both shoot cards evenly lit and square-on, which is exactly what kills
the diffraction a phone sees live — so the `foil` and `foil-text` degradations
in `augment.mjs` are a MODEL of foil, and a model can only ever confirm the
failure it was built to show. These photos are the evidence that the model is
honest. Where they disagree with it, they win.

## Why they live here and not on the fixtures branch

`harness-fixtures` is machine-generated and CI **force-pushes** it on every
run of `.github/workflows/scan-harness.yml`. A photograph cannot be
regenerated by the fetcher, so anything stored there is one workflow run away
from being gone. These are committed to the source tree instead.

Keep them small — downscale to ~1600px on the long edge before committing
(that is `CAPTURE_MAX_EDGE` in `lib/camera.ts`, so nothing above it survives
the resize the harness does anyway).

## Running them

```sh
node tests/harness/run-matrix.mjs --photos-only            # just the photos
node tests/harness/run-matrix.mjs --photos                 # battery + photos
node tests/harness/run-matrix.mjs --photos-only --verbose
```

A photo cell **bypasses `compose()`** — it already contains the lens, the
sensor, the lighting and the hand shake that the degradations exist to
simulate, so composing it again would measure a camera nobody owns. The only
thing done to it is the resize above.

## Adding one

Drop the image in this directory and add a row to `manifest.json`:

```json
{
  "photos": [
    {
      "key": "ygo-ultra-blue-eyes",
      "file": "ygo-ultra-blue-eyes.jpg",
      "game": "yugioh",
      "name": "Blue-Eyes White Dragon",
      "label": "photo-ultra",
      "note": "gold foil name, handheld, warm indoor lamp"
    }
  ]
}
```

- `name` is the ground truth, graded exactly like a fixture: right game, and
  name similarity ≥ 0.9.
- `label` is what the cell is called in the report grid (defaults to `photo`).
  Group like with like — `photo-ultra`, `photo-secret`, `photo-plain` — so a
  per-label column shows which finish is failing.
- `note` is for humans. Record the lighting and whether the card was held or
  flat; when a cell fails, that is the first thing worth knowing.

## Grading a photo run honestly

A photo cell can only pass if its card is in the captured API universe — the
stubs answer from `tests/harness/fixtures`, which holds the fetcher's picks
plus a few substring pools, not the whole catalogue. The first eight photos
scored 1/8, and seven of those failures were cards the stubs cannot return at
all; one of them ("Duel Tower") had already been read perfectly. **Check
membership before reading anything into the number**, and read the traces
rather than the score:

```sh
grep -ril "Card Name" tests/harness/fixtures/api/
```

To grade a photo properly, add its card to the picks in `fetch-fixtures.mjs`,
let CI regenerate `harness-fixtures`, re-pull, and re-baseline (lesson 3).

## Binder pages

`--binder --cards="A|B|C"` records an unordered MULTISET of names in a
separate `binders` list, because a nine-card photo is a different kind of
ground truth from one card and must never be graded as one. The single-card
runner ignores that list.

Grade them with:

```sh
node tests/harness/run-matrix.mjs --binders-only     # just the pages
node tests/harness/run-matrix.mjs --binders          # battery + pages
node tests/harness/preview.mjs --detect              # draw the boxes and LOOK
```

A page run reports three numbers, and they fail independently:

- **detected** — how many card-shaped regions the sweep found. A card never
  found cannot be misread; that is a detector fix, not an OCR one.
- **identified** — how many of the truth names were matched, greedily, at the
  same 0.9 similarity bar a single cell is graded at.
- **WRONG** — confidently identified, matching nothing left on the page. Watch
  this one hardest. A page files ~9 rows from one confirmation, so a wrong card
  here costs nine times what it does in single scanning, and a card the
  detector found TWICE lands here too — a duplicate row is a wrong row.

**Shoot pages at full resolution.** The "downscale to ~1600px" rule above is
right for a single card and wrong for a page: at 1600 a 3x3 grid leaves each
card ~370px wide, well under the ~790px where a printed collector line stops
being legible, so the identification numbers are a floor set by the photo
rather than by the pipeline. The app decodes a page at `PAGE_MAX_EDGE` (3200,
lib/multiscan.ts) for exactly this reason.

## What is worth photographing

The point is finishes the scans cannot show, so shoot the same card the way a
user would rather than the way a catalogue would:

- **Yu-Gi-Oh Ultra Rare** — gold foil name on the beige bar. Coloured text on
  neutral ground, the inverse of what the chroma pair was built for.
- **Yu-Gi-Oh Secret Rare** — silver/mirror name. Near-neutral at every tilt,
  so every intensity projection collapses; this is the case with no other
  answer.
- **A plain non-foil control, same phone and lighting.** Cheap, and it is what
  separates "foil is hard" from "these photos are hard". Without it a failing
  foil photo proves nothing.

Hold the card at the angle where the foil actually flares — a photo taken to
be readable models a problem nobody has.
