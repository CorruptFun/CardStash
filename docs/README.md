# Cardstock — build documentation

Everything about how this app is built, in the order it makes sense to learn
it. Written so that a person or an agent picking the repo up cold can answer
"what is this, how does it work, and what breaks if I change it" without
reading 23k lines of source.

**Cardstock** is a camera-first TCG scanner and collection portfolio. It is a
Vite + React 19 + TypeScript PWA with **no backend**: every card you own, every
deck, every friend and trade lives in IndexedDB on the device. Card data and
prices come from public card APIs; scanning runs entirely on-device (Tesseract
+ pixel analysis). The only server in the repo (`server/`) is an *optional*
self-hosted sync box the user opts into — the app must work fully without it.

Live: <https://corruptfun.github.io/CardStash/> · Source of truth: `main`.

## Three rules that outrank everything else here

1. **Never commit build output to `main`.** `dist/` is gitignored. `gh-pages`
   is regenerated by CI from `main` on every push and is force-overwritten —
   never edit or hand-push it. `harness-fixtures` is likewise machine-generated;
   never merge it.
2. **Never change scan-pipeline code without running the matrix before and
   after** (`npm run test:scan`). See [testing.md](testing.md).
3. **Always push your source changes before a session ends.** This tree was
   once reconstructed from a deployed bundle because the source lived only in
   an ephemeral session. Work that exists only as a deploy is work that is lost.
